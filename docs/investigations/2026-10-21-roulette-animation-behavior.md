# 調査: ルーレット各方式のアニメーションを一般的な挙動に寄せる

- 日付: 2026-10-21
- ステータス: 完了
- 関連する設計ドキュメント: (作成後にリンクを追記)

## 背景・目的

4種類のアニメーション方式(円形ルーレット・スロットマシン・ドラムロール・カードめくり)の動きが「一般的なルーレット演出と違う気がする」という報告。方式ごとに一般的な挙動とのズレを洗い出し、どう直すかの方針を決める。

ユーザーと合意した前提(調査中に確認):

| 項目 | 決定 |
| --- | --- |
| 範囲 | 4方式すべて。1つのPRにまとめる |
| 基準 | Web のルーレットツール並み(前回の位置から回る、区画内のランダムな位置で止まる、なめらかに減速)。跳ね返り・バウンス・効果音はなし |
| カードめくり | 名前どおり「裏向きのカードがめくれる」演出に作り直す。光が裏向きカードの上を移動して減速し、止まった1枚がめくれる。その後、残りのカードもめくって誰だったか見せる |
| スロット | 3列とも当選者で揃える(今と同じ)。左から順に止まる |
| 複数人選出 | すでに当たった人は次の回で盤面から外す |
| prefers-reduced-motion | 今回は対応しない |

## 現状の把握

呼び出し側は `js/ui-controller.js` の 591〜690 行付近。アニメーションのインスタンスを1つ作り `initialize(members)` を1回呼んだあと、選出人数分 `spin(selected[i], { duration })` を同じインスタンスに対して繰り返す(間に 500ms 待機)。`duration` はスライダー(3〜10秒、既定6秒、`index.html:44`)の値をミリ秒にしたもの。選出結果 `selected` はアニメーション前にすべて確定しており、重複はない。

### 円形ルーレット(`js/animations/roulette-wheel.js`)

| 一般的な挙動 | 現状 |
| --- | --- |
| 前回止まった位置から回り始める | `spin` の先頭で `this.rotation = 0` にリセットするため、2回目以降は盤面が瞬間的に初期位置に戻ってから回る |
| 区画内のランダムな位置で止まる | `calculateTargetAngle` が必ず区画の中央に針が来る角度を返す(コメントは「白線回避」だが実際は中央固定) |
| なめらかに減速して止まる | easeOut cubic(`1 - (1-p)^3`)。これ自体は一般的 |
| 当たった人は次の回で外れる | `members` は最初の `initialize` のまま変わらない |

その他: `calculateTargetAngle`・`getPointerIndex` の上に同じ JSDoc が何重にも重なり、インデントが崩れている(機能には影響なし)。

0リセットは前回のバグ修正(`.kiro/specs/animation-result-mismatch-fix/bugfix.md` の 2.2)で意図的に入れたもの。当時の不具合は「前回の rotation を残したまま、目標角を絶対値で計算していた」ことが原因で、リセットはその回避策。現在角からの相対で目標角を計算すれば、リセットしなくても針と結果は一致する。

### スロットマシン(`js/animations/slot-machine.js`)

| 一般的な挙動 | 現状 |
| --- | --- |
| 設定した時間で回る | `options.duration` を読むが使っていない。列は 1s/2s/3s で止まり、スライダーが効かない(仕様 3.5「設定を正しく適用」にも反する) |
| 絵柄が上から下へ流れる | `translateY` を負の方向に動かすため、絵柄が下から上へ流れる |
| 一気に最高速になり、一定速度で回ってから順に減速して止まる | 列ごとに `cubic-bezier(0.25, 0.1, 0.25, 1)`(CSS の `ease`)の transition 1本。ゆっくり動き出して加速し減速するため、定速で回っている時間がない。停止の早い左列は回転量も少ない |
| 前回の停止位置から回り始める | 毎回 `translateY(0)` にジャンプしてから動く |
| 当たった人は次の回で外れる | リールは `initialize` で作ったまま |

その他: 停止位置の計算が `itemHeight = 120` の決め打ち(CSS の `.slot-item { height: 120px }` と対応)。スマホ幅のメディアクエリでは `.slot-item` の高さを変えていないので現状はずれないが、CSS と JS の二重管理になっている。リールは「シャッフル済みメンバー × 10回」の DOM を持ち、5周目で止める。

### ドラムロール(`js/animations/drum-roll.js`)

| 一般的な挙動 | 現状 |
| --- | --- |
| だんだん遅くなって、切り替わりの流れのまま当選者で止まる | メンバーを順番に切り替え、時間が来たら直前の表示と無関係に当選者へ切り替える。直前に当選者が出ていれば同じ人が2回続けて表示される |
| 減速の終わりで止まる | 切り替え間隔は 50ms→500ms。最後の1回の待ちが最大 500ms あるため、終了が `duration` より最大で約 0.5 秒遅れる |
| 当たった人は次の回で外れる | `members` は変わらない |

`intervalId` は使われていない(`setTimeout` の連鎖で動いている)ため、`destroy` しても走っている切り替えは止まらない。

### カードめくり(`js/animations/card-flip.js`)

| 一般的な挙動 | 現状 |
| --- | --- |
| 裏向きのカードがめくれて当選者が分かる | カードは最初から表向き。めくる演出がない |
| 光が減速して当選カードで止まる | 100ms 間隔の一定速度でハイライトし、全体の70%が過ぎたら突然当選カードに切り替わる |
| ランダムに光る | `sort(() => Math.random() - 0.5)` で一度だけ並べ替え、その順序を繰り返す(同じ順で何周もする) |
| 複数人選出の2回目以降も正しく表示される | **バグ**: `card-flip-selected`・`card-flip-unselected` を `spin` のたびに外さないため、2回目は1回目の当選カードが光ったまま、他のカードも半透明のままハイライトが走る |

### 既存テスト

- `tests/unit/animation-bug-exploration.test.js` … 円形の1回目・2回目で針が指す人と選出結果が一致すること、スロットの列停止時間が正で左から順になること
- `tests/unit/animation-preservation.test.js` … 円形の duration・最低回転数(5回転以上)、スロットの列1・2の停止時間差、スロット停止後の配置
- `tests/unit/roulette-wheel.test.js` … 円形の初期化(区画数など)

0リセットや「列は 1s/2s/3s」を前提にしている箇所は、今回の変更で書き換えが必要になる。

## 選択肢の比較

### 1. 方式ごとの直し方: 今のクラスを直すか、作り直すか

| 選択肢 | メリット | デメリット | 備考 |
| --- | --- | --- | --- |
| 案A: 各クラスの `initialize`/`spin`/`destroy` の形は保ったまま、中身を方式ごとに直す | 呼び出し側(`ui-controller.js`)とテストの構造をほぼ維持できる。差分が方式ごとに閉じる | 共通の処理(時間配分、当選者を外す処理)が各クラスに散らばる | |
| 案B: 共通の基底クラスやタイムライン部品を作り、4方式をその上に作り直す | 共通処理が1か所にまとまる | 差分が大きく、レビューしにくい。4方式で動きの仕組み(Canvas / CSS transition / setTimeout)が異なるので共通化の効果が薄い | |

### 2. 当選者を盤面から外す方法

| 選択肢 | メリット | デメリット | 備考 |
| --- | --- | --- | --- |
| 案A: 呼び出し側が2回目以降の `spin` 前に、当選済みを除いたメンバーで盤面を作り直す(`initialize` を呼び直す、または `setMembers` 相当を追加) | アニメーションクラスは「渡されたメンバーで回すだけ」のまま単純。除外のルールが呼び出し側1か所にある | 円形・スロットで「前回の位置から回る」と両立させるには、作り直し時に回転位置を引き継ぐ必要がある | |
| 案B: 各アニメーションクラスが `spin` 終了時に当選者を自分で外す | 呼び出し側の変更が少ない | 除外ルールが4か所に分散する。抽選エンジンの結果と盤面がずれる余地が増える | |

### 3. 「前回の位置から回る」と「止まった位置 = 結果」の両立(円形・スロット)

| 選択肢 | メリット | デメリット | 備考 |
| --- | --- | --- | --- |
| 案A: 現在角(現在位置)から目標までの差分を計算し、最低回転数を足して回す | 一般的なツールと同じ動き。結果との一致もテストで検証できる | 仕様 2.2(常に初期位置から回す)を改訂し、該当テストを書き換える必要がある | 区画内のランダム位置は、区画の端から一定の余白を取った範囲で選ぶ |
| 案B: 0リセットは残し、リセットを見せないように盤面の描画だけ前回位置からつなぐ | 既存テストの前提を残せる | 内部状態と見た目が二重になり、前回のバグと同種の不一致を招きやすい | |

## 推奨アプローチ

各論点とも **案A** を推奨する。

- 4方式のクラスの形(`initialize`/`spin`/`destroy`)は保ったまま、中身を方式ごとに直す。共通化は「区画内のランダム位置」「時間の配分」など小さな関数に留める。
- 当選者の除外は呼び出し側(`ui-controller.js`)が担い、2回目以降は残りのメンバーで盤面を作り直す。円形・スロットは作り直しても見た目の回転位置を引き継げるようにする。
- 円形・スロットは現在位置からの相対で目標を計算し、0リセットをやめる。止まった位置 = 結果の検証は維持し、テストは新しい前提に合わせて書き換える。

方式ごとの目標の挙動(設計で詳細化する):

- **円形**: 前回止まった角度から回り始め、最低回転数を回ったあと、当選者の区画内のランダムな位置(境界の白線から余白を取る)で easeOut で止まる。2回目以降は当選済みの区画がない盤面で回す。
- **スロット**: 絵柄が上から下へ流れる。全列が同時に最高速で回り始め、一定速度で回ったあと、左から順に減速して当選者で止まる。最後の列が止まるまでの時間を `duration` に合わせ、列の停止時刻は `duration` に対する比率で配分する。前回の停止位置から回り始める。
- **ドラムロール**: 切り替え間隔をだんだん長くし、最後の切り替えがちょうど当選者になるよう、開始位置(または切り替え回数)を逆算する。当選者が2回続けて表示されない。終了時刻は `duration` から大きくずれない。
- **カードめくり**: 全カードを裏向きで並べ、光が裏向きカードの上をランダムに移動しながらだんだん遅くなり、当選カードで止まる。止まったカードがめくれて当選者が分かり、少し遅れて残りのカードもめくれる。2回目以降は前回の状態を持ち越さない(当選済みのカードは盤面から外す)。

## 制約・リスク

- **止まった位置 = 結果**: 前回のバグ修正の主目的。相対計算・ランダム位置・リール方向反転のどれもこの一致を壊しうるので、全方式で「表示された当選者 = `selectedMember`」をテストで検証する。
- **既存仕様の改訂**: `.kiro/specs/animation-result-mismatch-fix/bugfix.md` の 2.2(常に初期位置から回す)と、`.kiro/specs/animation-selector/requirements.md` の「各列の停止時間差: 1秒」「カード: グリッドで光る」は今回の方針と食い違う。`.kiro/specs/` は編集しない方針(`docs/process/project-dev.md`)なので、設計ドキュメント側で「この記述を置き換える」と明記する。
- **Jest(jsdom)の制約**: `requestAnimationFrame`・CSS transition・Canvas は jsdom では実際には動かない。既存テストは Canvas のモックや状態値の検証で対応している。新しい動きも「状態値・計算結果」を検証できる形(時間配分や目標位置を純粋な関数に切り出す等)にする。
- **CSS 3D 変形(カードめくり)**: `transform: rotateY` と `backface-visibility: hidden` で表裏を作る。主要ブラウザで対応済み。
- **スロットの DOM 量**: 30人のチャネルで「シャッフル × 10回」= 300要素 × 3列。回転量を増やすなら繰り返し数との関係に注意する(足りなくなると途中で空白が見える)。
- **duration の意味**: 今は方式ごとにばらばら(スロットは無視、カードは70%をハイライト、ドラムは最大0.5秒超過)。「回り始めてから当選者が確定するまで」にそろえるのが自然だが、カードの「残りもめくる」時間を含めるかは設計で決める。

## 未解決の疑問・要確認事項

設計フェーズで決める(ユーザー確認が必要なものは設計後のゲートで提示する):

1. 円形の区画内ランダム位置の余白(区画幅の何%を避けるか)。区画が細い大人数(30人で12度)でも境界ぎりぎりに見えない値にする。
2. スロット・ドラムロールの最低回転量(人数が少ないときに回転が物足りなくならないか、多いときに速すぎないか)。
3. `duration` に「当選者確定後の演出(カードの残りめくり、ドラムの強調)」を含めるか。
4. 当選者を外したあと盤面が1人だけになる回(例: 3人中3人選出の最後)の見せ方。回す必要がない場合も演出を省かないか。
5. スロットの `itemHeight` の決め打ちを、実際の要素の高さから測る方式に変えるか(今は CSS と一致しているので必須ではない)。
